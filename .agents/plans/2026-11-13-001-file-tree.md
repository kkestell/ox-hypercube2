# File tree in the right sidebar

## Goal

Show a live file tree of the viewed session's directory in the right sidebar,
read and watched by `oxd` one folder at a time.

**Brief:** `.agents/briefs/2026-11-13-001-file-tree.md`

## Related code

- `crates/ox-protocol/src/messages.rs` — `Method`, `ServerMessage` (untagged),
  and the stream messages `Event` and `List`. The directory watch is a third
  kind of stream beside them.
- `crates/ox-protocol/src/client.rs` — `Route`, `Unsubscribe`, `Watch`, and
  `read_loop`. A directory watch follows `Watch` exactly.
- `crates/oxd/src/conn.rs` — `serve` starts `watch` and `forward` as tasks in
  `subscriptions`, ended by `unsubscribe`; `watch` is the pattern for the new

  "unexpected method" arm lists the connection's own methods).
- `crates/oxd/src/main.rs` — builds the `Daemon`.
- `crates/ox/src/lib.rs` — `App`, `Task`, the `watch` and `view_session`
  commands that forward streams over Tauri channels.
- `ui/src/components/Workbench.tsx` — the right panel is an empty `<aside>`.
- `ui/src/features/sessions/SessionList.tsx`, `ui/src/styles/sessions.css` —
  the sidebar layout (`.sidebar`, `.sidebar-header`, `.session-list`) and the
  row kind (`.session` with `.select`, `.status`, `.title`); the Archived
  toggle is already a chevron row of that kind.
- `ui/src/features/conversation/useConversation.ts` — a stream hook that

  `listings_until` style of waiting on a stream.

## Decisions

- **Protocol.** `directory.watch { path }` starts a stream like `watch`: the
  answer, then `ServerMessage::Directory { subscription, entries }` at once
  and each time the entries differ from the last sent. `unsubscribe` ends it.
  `path` must be absolute (`INVALID_REQUEST` otherwise). `DirEntry { name:
  String, kind: EntryKind }`, `EntryKind::{File, Directory}` (snake_case). A
  symlink takes its target's kind; a broken one is a `file`. Entries are
  sorted by name, so equal listings compare equal. A directory that does not
  exist or cannot be read lists no entries; the watch keeps going and lists it
  once it can be read. That covers a worktree session in `starting`, an
  archived session, and a deleted folder that comes back. `entries` is a
  required `Vec`, so the untagged `ServerMessage` cannot confuse it with
  `List`.
- **The hidden list** lives in `oxd` (`HIDDEN` in `directories.rs`): `.git`,
  `.hg`, `.svn`, `.jj`, `CVS`, `.DS_Store`, `Thumbs.db`, matched by exact
  name at every depth, whatever the entry's kind (a worktree's `.git` is a
  file). Names that are not UTF-8 are left out.
- **One shared watcher.** `Directories` holds one `notify::RecommendedWatcher`
  (FSEvents on macOS) and a map from canonical directory path to `Watched {
  changed: watch::Sender<()>, watchers: usize }`. Each directory is watched
  `NonRecursive`, once however many streams want it, and unwatched when its
  last stream ends. The event handler, for each event path `p` (ignoring
  `EventKind::Access`), signals the entries for `p` and `p.parent()`; on
  `need_rescan()` or a watcher error it signals every entry. Paths are
  canonicalized before they key the map because FSEvents reports real paths
  (`/private/var/...` for `$TMPDIR`). One watcher, rather than one per
  stream, keeps to one FSEvents stream and one inotify instance.
- **Following a missing directory.** A stream watches the nearest existing
  ancestor-or-self of its path. Each wake reads the directory; when the read
  fails, or the watch is on an ancestor, it resolves the nearest ancestor
  again and moves the watch there. It registers the watch before reading, so
  a change during the read wakes it again; `watch::Receiver` coalesces bursts
  into one read. Registration and reading run in `spawn_blocking`.
  Leave a TODO in `directories.rs`: on Linux a directory deleted and
  recreated between two reads keeps a stale inotify watch; revisit if the app
  runs on Linux.
- **App core.** `App.directories: Mutex<HashMap<u32, Task>>`, keyed by the
  Tauri channel's ID. `watch_directory(path, channel)` and
  `unwatch_directory(channel_id)` are synchronous, so the webview's watch and
  unwatch calls run in order, as `view_session`'s do. The `watch` command
  clears `directories`: a new workspace watch means a reload or a reconnect,
  and in both the webview starts its directory watches again once the watch
  connects, so this ends watches a reloaded webview left behind.
- **UI structure.** Each open folder is a `Folder` component whose
  `useDirectory(path, connection)` watches it, so mounting a folder reads it
  and collapsing ends the watches of everything below it. The tree's root is
  `session.cwd`; the persisted state names folders by their path relative to
  it. The UI sorts folders first, then by
  `Intl.Collator(undefined, { numeric: true, sensitivity: "base" })`, as VS
  Code's explorer does.
- **Persisted state.** `treeState.ts` keeps `{ open: string[], scrollTop:
  number }` in `localStorage` under `fileTree:<session id>`. An open folder
  under a collapsed parent stays in `open`, so it reopens with its parent, as
  in VS Code. `forgetDeletedTrees(sessions)` runs in `App` on each listing
  once `connection > 0`, and removes the state of every session not in the
  list, so a delete from any client, `oxctl` included, removes it.
- **Scroll restore.** The tree's body restores the saved `scrollTop` while a
  restore is pending: a `ResizeObserver` on the tree content sets
  `scrollTop` each time the content grows, and the restore ends when
  `scrollTop` reaches the saved value or the user scrolls (`wheel`,
  `pointerdown`, `keydown` on the body). `onScroll` saves only once the
  restore has ended, so clamped attempts do not overwrite the saved value.
- **Shared sidebar abstractions.** The right sidebar is the same kind of
  region as the left one, and a tree row the same kind of element as a
  session row, so both go through shared pieces:
  - `components/Sidebar.tsx` renders `.sidebar` > `header.pane-header
    .sidebar-header` (with optional `actions`) > `.sidebar-body` (the
    scrolling region, taking a `ref` and `onScroll`). `SessionList` and
    `FileTree` both use it. `.session-list` becomes `.sidebar-body`.
  - The row rules on `.session` (height, radius, hover, selected, `.select`,
    `.title`) move to a `.sidebar-row` class. Session rows are `sidebar-row
    session`, the Archived toggle `sidebar-row archived-toggle`, tree rows
    `sidebar-row tree-row`. Rules that belong only to sessions (row actions,
    branch status, exited dimming, title mask) stay on `.session`.
  - A tree row indents by `--depth` times a new token `--tree-indent`
    (`calc(var(--spacing) * 2)`, VS Code's 8 px), added to the row's padding.
    That and the scrolling region are the only new CSS.
- **Row content.** A folder row is a `button.select` with `aria-expanded`,
  a `.status` holding `ChevronRight` or `ChevronDown`, and the name in
  `.title`, like the Archived toggle. A file row is a `div.select` with an
  empty `.status`-sized spacer where the chevron would be, a `.status`
  holding lucide's `File`, and the name. The list is `ul[role=tree]` with
  `li[role=treeitem]` rows, a folder's children in a nested `ul[role=group]`.
- **Hidden panel.** `Workbench` renders its `right` content only while the
  right panel is visible, so a hidden tree reads nothing; showing it again
  restores from the persisted state.

## Check your assumptions

1. **Which directory is the root.** Kept.
   - **Decided:** `session.cwd`. For a workspace that is a subdirectory of its
     repository, a worktree session's `cwd` is the same subdirectory of the
     worktree, so its tree matches the checkout session's tree.
   - **Consequences:** A worktree session of a subdirectory workspace shows
     that subdirectory, not the worktree's top level.
   - **Alternative:** `worktree.path` for worktree sessions.
   - **Trade-offs:** `cwd` matches what the agent sees and what a checkout
     session shows; the top level shows the whole repository, including files
     outside the workspace.
2. **New dependency `notify` in `oxd`.** Kept.
   - **Decided:** `notify` 8 with its recommended watcher (FSEvents on macOS,
     inotify on Linux), one watcher for the daemon.
   - **Consequences:** `oxd` gains `notify` and its platform crates. Changes
     under a watched folder that is collapsed in the tree (a build in
     `target/`) still reach the FSEvents callback, which `notify` filters out;
     the cost follows the rate of changes, not the size of the workspace.
   - **Alternative:** Polling each open folder on a timer.
   - **Trade-offs:** `notify` is event-driven and immediate; polling needs no
     dependency but reads every open folder on every tick and lags by the
     interval.
3. **Tree rows look like session rows.** Kept.
   - **Decided:** Tree rows share `.sidebar-row` with session rows: the same
     height (`--sidebar-row-height`, 32 px), padding, radius, and hover.
   - **Consequences:** Rows are taller than VS Code's 22 px, so fewer files
     fit. `.session` is split into `.sidebar-row` plus `.session`, and the e2e
     XPath selectors on `@class="session"` change with it.
   - **Alternative:** A compact row height for tree rows, as a second size of
     the shared row.
   - **Trade-offs:** One row size keeps the sidebars consistent; a compact
     size fits more files and matches VS Code, at the cost of a second row
     size to design.
4. **Files are inert.** Kept.
   - **Decided:** Clicking a file does nothing: no selection highlight, no
     focus, and no arrow-key tree navigation. Folders toggle on click, Enter,
     and Space, as buttons.
   - **Consequences:** The tree does not behave like VS Code's under the
     keyboard.
   - **Alternative:** A focusable tree with a selected row and VS Code's
     arrow-key navigation.
   - **Trade-offs:** Selection and keyboard navigation are a self-contained
     widget worth building with file opening; now they would select rows that
     do nothing.
5. **The right sidebar has an empty header.** Kept.
   - **Decided:** The right sidebar uses the shared `Sidebar` with a
     `pane-header` that holds nothing, so its first row lines up with the
     left sidebar's content. It shows no title and no root folder name.
   - **Consequences:** 28 px of empty space above the tree.
   - **Alternative:** VS Code's section header naming the root folder
     (uppercase, as the workspace headers on the left).
   - **Trade-offs:** The empty header adds no text; the root name tells a
     worktree from a checkout at a glance.
6. **No `oxctl` command.** Kept.
   - **Decided:** `oxctl` gains nothing; the daemon tests drive
     `directory.watch` through `Client`.
   - **Consequences:** Agents cannot list a directory through `oxd` from the
     command line.
   - **Alternative:** `oxctl ls-dir <path>` printing one listing.
   - **Trade-offs:** Leaving it out keeps the change to the desktop workflow;
     the command would be a few lines and let agents check the hidden list.
7. **The panel still starts hidden.** Kept.
   - **Decided:** Panel visibility stays as it is: hidden at each start, and
     the tree reads nothing while hidden.
   - **Consequences:** After a restart the tree's open folders and scroll
     come back once the user shows the right panel.
   - **Alternative:** Persist which panels are visible.
   - **Trade-offs:** Out of the brief's scope; persisting would show the tree
     immediately after a restart.

## Test plan

- `crates/oxd/tests/daemon.rs`, `directory_watch_follows_changes`: in a temp
  directory with `a.txt`, `sub/`, `.git/`, and `.DS_Store`, a
  `watch_directory` lists `a.txt` (file) and `sub` (directory) only, in name
  order; creating `b.txt` lists it; renaming `a.txt` to `c.txt` lists the new
  name; removing `sub` drops it. Each step waits for the listing that shows
  it.
- Same file, `directory_watch_lists_a_directory_once_it_exists`: watching a
  path whose parent does not exist yet lists no entries; creating the parent,
  then the directory with a file, lists the file. This is the worktree root
  that appears during startup. It fails if the stream does not move its watch
  down from the ancestor.
- `client.rs` unit test `dropping_a_directory_watch_unsubscribes`, as
  `dropping_a_watch_unsubscribes`.
- `ox-protocol` `server_message_round_trip`: add a `Directory` message, and a
  `directory.watch` request in `request_round_trip`.
- `ui/e2e/specs/files.e2e.ts`: with a session in a folder holding `a.txt`
  and `sub/inner.txt`, showing the right panel lists `sub` and `a.txt`;
  writing `b.txt` with `fs` adds its row; expanding `sub` shows `inner.txt`;
  viewing another session and coming back shows `sub` still expanded.
- `make check`, `make e2e`, `make smoke-claude`.

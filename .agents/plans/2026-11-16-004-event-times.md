# Event times and run timeline times

## Goal

Events carry no time, so the run view shows only each step's start time. Give every event the time `oxd` recorded it, save it with the event, and carry it on every conversation item the desktop receives. Record when a run ends. The run view then shows each agent message's time, and the run's failure notice its end time, as `HH:MM` in the gutter beside it, as it shows a step's start time.

## Related code

- `crates/oxd/src/store.rs` — `Store::with` creates the schema; the `events` and `runs` tables; `Store::events`, `write_events` (`INSERT INTO events SELECT ?1, ?2, ?3 ...`), `add_run`, `runs`, `update_run`; test helpers `event` and `add_run`.
- `crates/ox/src/conversation.rs` — `Conversation::apply` folds an event into `Item`s; `coalesce` merges an item into the earlier one with its key; test helper `fold`.
- `crates/ox/src/lib.rs` — `view_session` coalesces the applied items of a session's history and live events and sends them to the webview.
- `crates/ox-protocol/src/client.rs` — test `close_session` builds an `Event`.
- `ui/src/lib/protocol.ts` — `Item`, `ConversationUpdate`, `RunInfo`.
- `ui/src/features/conversation/useConversations.ts` — `reduce` inserts or replaces items by key and appends text.

## Decisions

- **Event time.** `Event` gains `recorded_at: u64`: when `oxd` recorded the event, in milliseconds since the Unix epoch. `State::append` sets it to `crate::daemon::now()`. Updates a starting agent replays get the time `oxd` recorded them.
- **Run end time.** `RunInfo` gains `ended_at: Option<u64>`: when the run succeeded, failed or was cancelled, unset while it runs and for an interrupted run, whose stop `oxd` did not see. `Run::end` sets it to `now()` for every state it is given. `update_run` takes and saves it.
- **Schema.** `events` becomes `(session_id, seq, recorded_at INTEGER NOT NULL, kind)` with the same key; `write_events` names its columns in the insert, and `Store::events` reads `recorded_at`. `runs` gains `ended_at INTEGER` after `created_at`; `add_run` and `runs` handle it.
- **Migration.** A throwaway script outside the repository, `/tmp/ox-migrate-event-times.py <database>`, using Python's `sqlite3`, in one transaction: when `events` has no `recorded_at` column (`pragma_table_info`), it creates `events_new` with the new definition, copies every event with its session's `created_at` as `recorded_at`, drops `events`, and renames `events_new`; when `runs` has no `ended_at`, it runs `ALTER TABLE runs ADD COLUMN ended_at INTEGER`. Runs that ended before keep `ended_at` unset. A database already migrated is left unchanged. `store.rs` has no migration code.
- **Item time.** `conversation.rs` gains `pub struct ConversationUpdate { pub recorded_at: u64, #[serde(flatten)] pub item: Item }`, the name the UI already uses. `apply` returns `Vec<ConversationUpdate>`, each item stamped with the event's `recorded_at`. `coalesce` takes and returns `ConversationUpdate`s and keeps the earlier `recorded_at` when it merges an item into the one with its key. `view_session` sends `ConversationUpdate`s. The `Item` variants are unchanged.
- **An item's time is when its key first appeared.** `reduce` in `useConversations.ts` keeps the existing item's `recorded_at` whenever an update replaces or appends to an item with its key, as `coalesce` does. A message's time is when its first text arrived; a tool call's when it started.
- **UI types.** In `protocol.ts`, `Item` becomes `{ recorded_at: number } & (...)` over its current union, and `request_resolved` in `ConversationUpdate` gets `recorded_at` too. `RunInfo` gains `ended_at: number | null`.
- **Rendering.** `runNotice` also returns `time: run.ended_at`. Each message `li` and the notice `li` start with `<time className="run-status-entry-time" dateTime={ISO}>{clock(time)}</time>` (the notice only when `ended_at` is set). The time sits in the gutter left of the connector, at the same left edge, width, colour and size as `.run-status-time`, vertically centred on the entry's first line. To keep it inside the scrolling list, `.run-status-messages` gets `margin-left: calc(-1 * var(--run-status-indent))` and its left padding grows by `--run-status-indent`; the dot and branch offsets, measured from the text, stay as they are. The notice shown under the steps when no step matches it, and the session view, show no times.

## Check your assumptions

1. **How event times are stored.** Changed: a `recorded_at INTEGER NOT NULL` column on `events`, with existing databases migrated in place.
   - **Decided:** A column on `events`, and on `runs` for `ended_at`.
   - **Consequences:** Every event has a time. Existing events get their session's creation time.
   - **Alternative:** A separate `event_times` table with an optional time.
   - **Trade-offs:** The column keeps the schema direct; a separate table only spares existing databases, which hold nothing worth keeping.

2. **Whether message times are always shown.** Kept.
   - **Decided:** Always, in the gutter like the step's start time.
   - **Consequences:** The gutter gets a time beside every message, so a busy step shows a column of mostly repeated `HH:MM` values.
   - **Alternative:** Show a message's time only while the message is hovered.
   - **Trade-offs:** Always shown reads at a glance and works without a pointer; hover keeps the gutter quiet but hides the times until sought.

3. **What gets a time.** Changed: every conversation item carries its time, and the run records its end time for the notice.
   - **Decided:** Every item through `ConversationUpdate`; `RunInfo.ended_at`. The run view shows the messages' times and the notice's.
   - **Consequences:** The session view receives times but shows none yet.
   - **Alternative:** Agent messages only, with no run end time.
   - **Trade-offs:** Every item makes times available to any view; messages only changes less.

4. **Time precision.** Kept.
   - **Decided:** `HH:MM`, the same `clock` the step's start time uses.
   - **Consequences:** Several messages within a minute show the same time.
   - **Alternative:** `HH:MM:SS` for messages.
   - **Trade-offs:** `HH:MM` matches the step time and stays narrow in the gutter; seconds tell close messages apart but widen the gutter and differ from the step time.

5. **Where the migration runs.** Changed: a throwaway Python script in `/tmp`, run when the work is done.
   - **Decided:** `/tmp/ox-migrate-event-times.py`, run on the development databases (`target/dev/oxd.sock.db` in `/Users/kyle/src/ox` and in each worktree that has one) while no `oxd` has them open. The installed `oxd` is running this workflow, and its old build cannot write events to a migrated table, so the installed database is migrated with the same script when the new build is installed.
   - **Consequences:** `store.rs` has no migration code. The script is not committed.
   - **Alternative:** Migration code in `Store::with`, run when each database is opened.
   - **Trade-offs:** The script keeps the repository free of one-off code; in-code migration needs no manual run but stays in `store.rs` until removed.

6. **Interrupted runs' end time.** Kept.
   - **Decided:** None. `oxd` marks a run interrupted when it starts again, not when the run stopped.
   - **Consequences:** An interrupted run's notice shows no time.
   - **Alternative:** Set `ended_at` when `oxd` marks the run interrupted.
   - **Trade-offs:** None shows no wrong time; the restart time shows a time, but one later than the run's actual stop.

## Test plan

- `store.rs`: `events_round_trip_in_order_across_batches` reads back each event's `recorded_at`. The run round-trip test saves `ended_at` through `update_run` and reads it back.
- `state.rs`: a new test records a change and checks the appended event's `recorded_at` lies between `now()` before and after.
- `messages.rs`: the round-trip tests include `recorded_at` and `ended_at`.
- `conversation.rs`: `apply` stamps each item with its event's time; `coalesce` of two chunks of one message at times 5 and 9 gives one update with `recorded_at` 5. `fold` keeps returning `Item`s for the existing tests.
- `crates/oxd/tests/runs.rs`: a step whose agent sends `messages 2 ...` has child events whose `recorded_at` are non-decreasing and between the step's `started_at` and now; a succeeded run's and a failed run's `ended_at` lie between their last step's `started_at` and now; a cancelled run's is set.
- `crates/oxd/tests/daemon.rs` (or wherever restored runs are tested): an interrupted run's `ended_at` is unset.
- `RunView.test.tsx`: messages at two times show those times, formatted as `clock` formats them, with `dateTime` set; a further chunk appended to the first message leaves its time; a failed run's notice under its step shows `ended_at`.

## Implementation plan

1. `messages.rs`: `Event.recorded_at` and `RunInfo.ended_at` with doc comments; the serialization tests. Update `Event` literals in `client.rs` and other tests.
2. `state.rs`: set `recorded_at` in `append`; the test.
3. `store.rs`: the schema, `write_events`, `Store::events`, `add_run`, `runs`, `update_run`; the store tests.
4. `run.rs`: `Run::end` sets `ended_at`; `daemon.rs` passes the run's `ended_at` through `update_run` when it marks a run interrupted. The `runs.rs` tests.
5. `conversation.rs` and `lib.rs`: `ConversationUpdate`, `apply`, `coalesce`; the tests.
6. `protocol.ts`, `useConversations.ts`, and the items and runs built in `core.tsx`, `scenarios.ts` (messages minutes apart, one failed run with `ended_at`), `RunView.test.tsx`, `Conversation.test.tsx`, `performance.test.tsx`.
7. `RunStatus.tsx` and `run-view.css`: the rendering in Decisions; the `RunView.test.tsx` tests.
8. Write `/tmp/ox-migrate-event-times.py`. Copy a development database to `/tmp`, run the script on the copy twice, and check with the new `oxd` that it opens and lists the copy's sessions and their events. Then stop `make dev` and run the script on each development database.

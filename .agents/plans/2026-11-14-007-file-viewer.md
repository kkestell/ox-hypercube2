# View live files beside the chat

## Goal

Clicking a file in the right sidebar opens one read-only file viewer to the right of the chat. Its header shows the filename, a file icon, and an X in the rounded pill shown in the supplied screenshot. Closing it removes the split. A draggable divider resizes the chat and viewer; both keep a minimum share of the available center width. Display plain monospaced text without wrapping, highlighting, or line numbers. Follow disk changes and restore each session's viewer and layout before its first painted frame when switching sessions.

## Related code

- `ui/src/App.tsx` — selects sessions and assembles the chat and file tree.
- `ui/src/components/Workbench.tsx` and `ui/src/styles/layout.css` — own pane headers, center layout, and existing sidebar/panel sashes.
- `ui/src/features/files/FileTree.tsx`, `treeState.ts`, and `useDirectory.ts` — file rows, session-local presentation persistence, and directory subscriptions.
- `crates/oxd/src/directories.rs` and `conn.rs` — shared non-recursive filesystem watches and subscription streams. Directory listings suppress unchanged entries, including ordinary edits to an existing file.
- `crates/ox-protocol/src/{messages,client,lib}.rs` and `crates/ox/src/lib.rs` — daemon wire types, stream routing, and Tauri channels.
- `ui/e2e/specs/files.e2e.ts` and `crates/oxd/tests/daemon.rs` — existing file-tree and directory-watch integration coverage.

## Decisions

- Add a focused `file.watch` daemon subscription, with `FileContent` carrying either text or a readable error. Use existing unsubscribe and client stream routing. Validate absolute paths. Register the existing shared directory watch on the file's parent before reading; reread when notified, suppress identical results, and handle ordinary edits, atomic replacement, deletion, and recreation. Read filesystem data off the async runtime thread. Keep file-stream code in `crates/oxd/src/files.rs`, with only request dispatch in `conn.rs`; do not expand the directory listing protocol or create another OS watcher.
- Read ordinary UTF-8 text; reject invalid UTF-8, NUL-containing binary data, and non-regular files clearly. Do not add image previews, editing, truncation, or arbitrary file-size limits. File read failures remain visible in the viewer and can recover on later notifications.
- Add paired Tauri watch/unwatch commands following directory-channel lifecycle ordering, with their channel tasks kept separately. Reconnection restarts file subscriptions and webview reload releases old ones.
- Keep viewer presentation state in a dedicated session-keyed store: selected relative path, chat width ratio, and viewer horizontal/vertical scroll. Keep presentation fields and content snapshots in browser memory, updating presentation synchronously as it changes. Restoration is required for session switches; app-restart persistence is outside this request. Prune deleted sessions alongside existing tree cleanup. A keyed session view initializes layout from this store in render; restore scroll before paint with a layout effect. Avoid effect-driven copying of the old session's state into the new session.
- Start the split at 50/50 and clamp the divider to 25–75% of the available chat/viewer width, excluding outer sidebars and the divider. Preserve the ratio when the surrounding width changes and when closing/reopening a file.
- Keep a file subscription alive for every session with an open viewer during the webview lifetime, even when another session is selected. Each stores only its current file's snapshot; closing, replacing a file, deleting a session, or tearing down the app releases the previous subscription. Thus revisiting a session can render its live cached contents immediately. Session changes and late messages must not overwrite another session or file. Keep the store notifications scoped so inactive file updates do not rerender the active conversation.
- Nest the chat/viewer split in the center's upper content region; leave the bottom panel and outer sidebar controls with their existing ownership. The viewer header shares the pane-header center line. Keep chat and composer together on the left and retain existing chat header actions. Add only the slot/layout support Workbench needs; put viewer-specific dragging and content in `SessionContent.tsx` and `FileViewer.tsx`. Reuse sash and icon-button styling and existing tokens. Add the pill and file padding tokens to tokens.css and viewer rules to files.css.

## Check your assumptions

None.

## Test plan

- Daemon integration tests through Client::watch_file: initial text, in-place edit, atomic replacement, deletion and recreation, invalid UTF-8/binary error, and unsubscribe cleanup using the existing stream-drop pattern. Cover absolute-path rejection and avoid reading special files.
- Extend the real desktop file E2E flow: click a nested file, show exact unwrapped text and filename, open a second file by replacing the first, close via X, and observe on-disk updates without clicking again.
- Drag the divider and verify both minimum shares, retention through window/sidebar sizing, and chat/composer layout. Switch between two sessions with different open files, ratios, and scroll offsets, including a session with no viewer. Observe the first painted session frame in the webview (for example with requestAnimationFrame sampling tied to session selection) to prove there is no intermediate wrong layout or stale other-session text. Change an inactive session's file before returning and verify its cached text updated.
- Verify deleted-session cleanup and that closing a viewer stops following it. Use bounded waits on observable results.
- Inspect the header against the supplied screenshot and adjacent pane headers in the running app; inspect overflow, selection/copying, scroll restoration, and narrow windows. Follow the repository's required checks for the changed UI, desktop, protocol, and daemon areas.

## Implementation plan

1. Add `FileContent`, `file.watch`, and file stream messages in `crates/ox-protocol/src/messages.rs`; add FileWatch routing, drop-to-unsubscribe, and exports in `client.rs` and `lib.rs`. Add meaningful routing/drop coverage beside existing client tests.
2. Add `crates/oxd/src/files.rs` for reading and streaming file snapshots through the existing directory watcher. Wire its module in `main.rs` and dispatch in `conn.rs`. Add behavioral integration tests in `crates/oxd/tests/daemon.rs`.
3. Add Tauri file watch/unwatch forwarding in `crates/ox/src/files.rs`, registering commands and managed state from `lib.rs`. Keep watcher ownership with the daemon. Define the UI FileContent wire shape in `ui/src/lib/protocol.ts`.
4. Add `ui/src/features/files/viewerState.ts` for synchronous session presentation state and cached subscription snapshots, with lifecycle ownership in `useFileViewers.ts`. Connect it in App.tsx, prune deleted sessions, and pass a stable file-opening callback through FileTree.tsx to real file buttons.
5. Add `ui/src/features/files/SessionContent.tsx` and `FileViewer.tsx` for chat/viewer layout, dragging, plain-text rendering, close, errors, and scroll restoration. Adjust Workbench.tsx and layout.css to let the two panes share the upper center region while preserving existing panel behavior. Add styles/files.css, import it in main.tsx, and extend tokens.css for the screenshot's pill and file content spacing.
6. Extend `ui/e2e/specs/files.e2e.ts` with viewer, live refresh, resizing, and first-frame restoration coverage and complete the test plan.

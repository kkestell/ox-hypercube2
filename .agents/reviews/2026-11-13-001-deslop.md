## High

### F1. Local merge can fast-forward to an obsolete task commit

High · Broken guarantees · Not fixed · `ui/src/features/sessions/MergeButton.tsx:31`

After a task commit is rewritten, **Merge into main** can publish the older commit and report that the live task was merged.

The button sends `to: comparison.tip` and `expected: comparison.compare_tip` (`ui/src/features/sessions/MergeButton.tsx:31–36`). Tauri forwards only those destination preconditions (`crates/ox/src/lib.rs:188–198`), and the daemon checks that the supplied SHA is a commit and the destination is unchanged (`crates/oxd/src/branches.rs:209–235`). The merge E2E refreshes the comparison immediately before the click (`ui/e2e/specs/merge.e2e.ts:50–64`). The checkout's notes record rewriting the source while leaving the destination unchanged (`.agents/todo.md:113–133`).

**Proposed fix**

Give local merge an expected source ref and tip alongside the destination precondition and check both during the ref update.

### F2. Branch moves overwrite ignored local files

High · Broken guarantees · Not fixed · `crates/oxd/src/branches.rs:276`

A successful move can replace an ignored configuration or other local file with the target commit's version.

`crates/oxd/src/branches.rs:249` passes `"--untracked-files=no"` to status, and line 276 runs `read-tree -u -m` after moving the ref. Git's implementation treats an ignored collision as safe to overwrite. The refusal in `docs/worktrees.md:81–84` covers untracked files. `crates/oxd/tests/worktrees.rs:2507–2516` covers only a non-ignored file. The checkout's local notes record a reproduction with an ignored `local.env` (`.agents/todo.md:55–64`). [Git read-tree implementation](https://github.com/git/git/blob/v2.50.1/builtin/read-tree.c#L214-L215) · [Git collision handling](https://github.com/git/git/blob/v2.50.1/unpack-trees.c#L2269-L2275)

**Proposed fix**

Refuse collisions with ignored files during the checkout update and preserve the ref and local contents on refusal.

### F3. Branch moves can overlap agent work in the same checkout

High · Broken guarantees · Not fixed · `crates/oxd/src/branches.rs:241`

An agent can begin a turn after the snapshot and continue running while Ox changes the checkout underneath it, despite the refusal described in `docs/worktrees.md:80–84`.

The move calls `busy(checkout)?` once and then awaits status, index refresh, ref update, and checkout update (`crates/oxd/src/branches.rs:240–277`). `refuse_busy` reads a snapshot of session states (`crates/oxd/src/daemon.rs:684–706`), and the prompt method goes directly to `session.prompt` (`crates/oxd/src/daemon.rs:233–235`). The existing test starts the prompt before requesting the move (`crates/oxd/tests/worktrees.rs:2531–2563`). The checkout's notes record the opposite order with a blocked Git command (`.agents/todo.md:67–111`).

**Proposed fix**

Coordinate branch moves and agent work for the affected checkout within Ox.

### F4. A gap in saved history can hide later committed events

High · Broken guarantees · Not fixed · `crates/oxd/src/store.rs:375`

Once a write has failed, replay can skip a later event that did commit or leave a forwarding task spinning.

The writer logs a failed transaction and then continues with later batches (`crates/oxd/src/store.rs:348–385`). On restart Ox reads the highest stored sequence and the persisted rows in sequence order (lines 130–149 and 189–194). Replay uses `events[start..]`, with `start` derived from the requested sequence as if it were a vector offset (`crates/oxd/src/state.rs:727–734`). `Session::events_after` waits on the highest sequence and the forwarding loop relies on a row arriving (`crates/oxd/src/session.rs:471–477`, `crates/oxd/src/conn.rs:190–202`). The local notes record stored sequences `1, 3, 4, 5, 6, 7` and a subscription after `6` missing event `7` (`.agents/todo.md:137–170`).

**Proposed fix**

Find the replay start by the sequence on the stored events.

### F5. Archive accepts sessions before the agent has opened

High · Broken guarantees · Not fixed · `crates/oxd/src/daemon.rs:626`

Archiving an agent stuck in startup can block Delete. If initial startup fails first, Archive can succeed and the session can disappear after restart.

Archive takes `_lifecycle` before `session.started().await` (`crates/oxd/src/daemon.rs:611–627`). The wait ends when the session leaves `Starting` (`crates/oxd/src/session.rs:357–366`), while Delete needs the same guard (`crates/oxd/src/daemon.rs:579–580`). The sidebar offers Archive on starting rows (`ui/src/features/sessions/SessionList.tsx:181–187`), and `delete_while_starting` demonstrates the recovery path when Archive has not taken the guard (`crates/oxd/tests/daemon.rs:1006–1040`).

A failed initial ACP open reaches `Exited(previous)` with no agent session ID (`crates/oxd/src/state.rs:354–357`). Archive can proceed to `set_archived(id, true)` (`crates/oxd/src/daemon.rs:626–635`). Restart cleanup checks `saved.agent_session_id.is_some()` before deleting or scheduling cleanup (`crates/oxd/src/daemon.rs:76–87,118–128`), while the archive restart test starts with a session that completed a turn (`crates/oxd/tests/worktrees.rs:2161–2186`).

**Proposed fix**

Make Archive available after the agent opens and refuse earlier requests before waiting on startup.

### F6. Unarchive can restore a checkout while leaving the session archived

High · Broken guarantees · Not fixed · `crates/oxd/src/daemon.rs:650`

A retry can keep failing after the original error is corrected, because a valid checkout already exists while Ox refuses to load the archived session.

`worktree::restore(...).await?` runs before `set_archived(id, false)` (`crates/oxd/src/daemon.rs:650–656`), and a retry always calls `git worktree add` again (`crates/oxd/src/worktree.rs:595–615`). SQLite clears the flag with `DELETE FROM archived` (`crates/oxd/src/store.rs:329–336`). A Git post-checkout failure can also return an error after leaving the checkout installed. The recorded SQLite-trigger reproduction is in `.agents/todo.md:172–194`, and existing archive tests cover successful restore and Git refusals before creation. [Git worktree hook handling](https://github.com/git/git/blob/v2.50.1/builtin/worktree.c#L523-L547)

**Proposed fix**

Let a retry finish the existing archive transition when Git already registers the recorded path on the recorded branch.

### F7. Bundled desktop tool images are blocked by the content policy

High · Broken guarantees · Not fixed · `ui/src/features/conversation/Conversation.tsx:142`

The packaged UI can display a broken image element where `docs/acp-v2.md:112–113` says tool images are shown. The existing assertion can pass without image decoding.

The tool renderer sets its image URL to `data:${content.mime_type};base64,${content.data}` (`ui/src/features/conversation/Conversation.tsx:138–143`). The bundled CSP only allows `default-src 'self' ipc: http://ipc.localhost` (`crates/ox/tauri.conf.json:27–29`). The pinned Tauri 2.12.5 source adds script and style directives and forwards the policy as an asset header (`src/manager/mod.rs:81–106,425–439`, `src/protocol/tauri.rs:175–185`). The E2E only checks `img` with `toBeDisplayed()` (`ui/e2e/specs/session.e2e.ts:152–161`). [Content Security Policy image sources](https://www.w3.org/TR/CSP3/#directive-img-src)

**Proposed fix**

Permit the existing tool-image source in `img-src` and have the current E2E assertion check decoding.

### F8. An earlier slow selection can take over the desktop transcript

High · Broken guarantees · Not fixed · `ui/src/features/sessions/SessionList.tsx:118`

A user can click an exited session, switch to a live session, then be taken back to the earlier transcript when its load returns.

Selecting an exited session awaits `invoke("load_session", ...)` before calling `onSelect(session.id)` (`ui/src/features/sessions/SessionList.tsx:114–121`). The daemon awaits the lifecycle lock and history load (`crates/oxd/src/daemon.rs:226–231`, `crates/oxd/src/session.rs:442–458`). A live-session click calls `onSelect` immediately through the same function, and `App.tsx:34–39` passes `setViewed` directly.

**Proposed fix**

Select immediately on the click and load the agent independently of the selection result.

### F9. Archived sessions offer settings changes that always fail

High · Broken guarantees · Not fixed · `ui/src/features/composer/Composer.tsx:135`

After archiving a session in the same daemon, the model, effort, or mode picker can still offer changes, each of which opens an error.

`Composer` disables prompt controls for `state === "exited"` at lines 27–28 and 103–127 but renders settings solely from `session.config_options.length > 0` at lines 135–145. Archiving a live session retains the last agent in its exited state (`crates/oxd/src/state.rs:469–472,695–703`), and its options remain visible in the listing (`crates/oxd/src/session.rs:419–424`). The setter rejects exited sessions (`crates/oxd/src/session.rs:493–501`). The archive test checks only the textarea (`ui/e2e/specs/archive.e2e.ts:89–98`).

**Proposed fix**

Disable or hide the agent settings while the underlying session cannot accept configuration changes.

### F10. The worktree guide overstates which commits keep a task branch alive

High · Comments and docs vs. code · Not fixed · `docs/worktrees.md:90`

A user who rewrites the original branch can delete a task believing its branch will be kept because it is the last ref containing its starting commit.

`docs/worktrees.md:90` says “every commit on it.” `docs/architecture.md:217–220` specifies “since the session's starting commit,” and `apply_branch_rule` passes the saved `base` after `--not` (`crates/oxd/src/worktree.rs:844–848,872–893`). The wire method also says “all its commits” (`crates/ox-protocol/src/messages.rs:146–149`). The branch-deletion test adds a unique commit after the base (`crates/oxd/tests/worktrees.rs:1564–1579`).

**Proposed fix**

Align the guide, README, and wire-method description with the implemented starting-commit rule.

### F11. The documented release bundle cannot run on its own

High · Comments and docs vs. code · Not fixed · `crates/ox/tauri.conf.json:31`

The documented bundle cannot start its own daemon from a fresh install. A daemon already running still does not supply the missing companion for the built-in agent.

`README.md:61–65` documents `npm run tauri build`. Tauri's build hook only runs `npm run build`, and the bundle configuration only lists icons (`crates/ox/tauri.conf.json:12–16,31–38`). No companion binary build or bundling step appears in the repository. The client calculates the daemon path with `current_exe()?.with_file_name("oxd")` (`crates/ox-protocol/src/client.rs:92–94`), and New Task resolves `claude-code-acp` the same way (`crates/ox/src/lib.rs:209–214`). An existing debug bundle corroborates the packaging setup by containing only `ox` under `Contents/MacOS`. [Tauri sidecar packaging](https://v2.tauri.app/develop/sidecar/#embedding-external-binaries)

**Proposed fix**

Document what the current build produces and where it expects the existing companion binaries.

### F12. The development README describes the wrong Claude startup behavior

High · Comments and docs vs. code · Not fixed · `README.md:85`

Opening a built-in agent session can launch Claude immediately. The README's development instructions give the wrong expectation about what a UI-created session does before the first prompt.

`README.md:85–88` says the bridge starts Claude only for a prompt. In `crates/claude-code-acp/src/main.rs:44–52` the bridge first answers `session/new`, then sends idle and starts the subprocess. The standalone bridge README gives a different account and says initialization happens “before answering” (`crates/claude-code-acp/README.md:138–139,211–216)). `docs/acp-v2.md:31–33` already describes asynchronous command discovery.

**Proposed fix**

Bring both READMEs into line with the actual startup sequence.

## Medium

### F13. The desktop reconnect test can pass with a stale transcript

Medium · Hollow tests · Not fixed · `ui/e2e/specs/connection.e2e.ts:14`

A correctly refreshed sidebar and cached transcript are enough for the test to pass while the new conversation subscription is broken.

The E2E asserts the same `chunk-1` element before and after restarting the daemon (`ui/e2e/specs/connection.e2e.ts:14–26`). `useConversation` would retain those items if the reconnect dependency were removed because the session ID stays the same (`ui/src/features/conversation/useConversation.ts:37–56`). `openSession` clicks the same already-selected ID (`ui/e2e/helpers.ts:165–170`, `ui/src/features/sessions/SessionList.tsx:116–121`).

**Proposed fix**

Require a new transcript event after reconnect while leaving the session selected.

### F14. The cold-resume command test discards an early valid update

Medium · Hollow tests · Not fixed · `crates/claude-code-acp/tests/protocol.rs:355`

A valid early command update can be discarded and the test can time out.

The response helper collects earlier notifications (`crates/claude-code-acp/tests/protocol.rs:122–130`). The cold-resume test drops that result at line 355 and then waits for the command notification at lines 356–361. Resume starts the native process before scheduling the response (`crates/claude-code-acp/src/bridge.rs:141–147`, `src/main.rs:75–77`), and command publication follows native initialization independently (`src/runner.rs:549–562`).

**Proposed fix**

Check notifications received before the reply as well as later ones when awaiting the initial catalog.

## Low

### F15. The client stores an unused daemon version

Low · Dead code · Not fixed · `crates/ox-protocol/src/client.rs:283`

The handshake retains a placeholder, a stored response, and an accessor that no client uses.

`Client` stores `hello: HelloResult` and initializes a dummy value before the real handshake (`crates/ox-protocol/src/client.rs:145–146,247–256`). Its only value consumer is `daemon_version()` (lines 283–285), which has no workspace callers. The daemon still compares protocol versions in `crates/oxd/src/conn.rs:77–90`.

**Proposed fix**

Keep the handshake validation and drop the unused client field and accessor.

### F16. The schedule tracker returns a change flag that nobody reads

Low · Dead code · Not fixed · `crates/claude-code-acp/src/background.rs:279`

The tracker has bookkeeping with no effect on the work it publishes.

`turn_ended` compares lengths and returns `changed` (`crates/claude-code-acp/src/background.rs:276–308`). Its sole production caller ignores that value and calls `release` unconditionally (`crates/claude-code-acp/src/updates.rs:119–122`). The inline test calls also ignore the return value.

**Proposed fix**

Return `()` and remove the unused change calculation.

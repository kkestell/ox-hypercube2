## F1. Pi transcripts title `ox` tool calls `Mcp__ox__set_title`

Low · Readability · Fixed · `crates/pi-acp/src/tools.rs:24`

Pi names MCP tools `mcp__<server>__<tool>`. `tools::title` capitalizes the first character of the tool name and reads a `path` argument, so a Pi session's `set_title` call shows in the transcript as `Mcp__ox__set_title`, with no argument, and `post_status_update` as `Mcp__ox__post_status_update`. The Claude bridge shows the same calls as `SetTitle` and `PostStatusUpdate` followed by their first string argument (`tool_display_name` and `tool_argument` in `crates/claude-code-acp/src/updates.rs`). Now that `oxd`'s instructions tell every Pi agent to call `set_title`, most Pi sessions show this row. The tool calls work; only their displayed title differs.

### Evidence

`updates.rs:164` passes Pi's tool name to `tools::title`. For `mcp__ox__set_title` the `match name` falls through to the `path` key, which the call's `{"title": ...}` arguments lack, so the title is the capitalized name alone. Pi's `pi-mcp/dist/naming.js` builds the `mcp__<server>` prefix.

### Fix

`tools::title` strips the `mcp__<server>__` prefix, shows the tool name in capitalized words, and falls back to the first string argument for MCP tools, so `set_title` shows as `SetTitle` followed by its title. A unit test in `tools.rs` covers it.

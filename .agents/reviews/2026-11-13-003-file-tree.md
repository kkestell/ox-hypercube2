## F1. Watching or unwatching a directory can drop other changes

Low · Correctness · Fixed · `crates/oxd/src/directories.rs:43`

Each `watch` and `unwatch` on `notify`'s FSEvents watcher stops the FSEvents stream and starts a new one from `kFSEventStreamEventIdSinceNow`. A change in another watched directory during that restart reaches no stream, and that folder's listing stays stale until something in it changes again. The stream that triggered the restart is not affected, because it reads its directory after registering. The window lasts the length of one stream restart, so it takes a folder opening or closing at the moment an agent writes into another open folder.

### Evidence

`notify-8.2.2/src/fsevent.rs`: `watch_inner` and `unwatch_inner` call `stop()` then `run()`, and the watcher is built with `since_when: kFSEventStreamEventIdSinceNow` and `latency: 0.0`.

### Fix

Added a TODO beside the Linux one on `Directories` naming the gap and the condition for revisiting it: open folders seen to go stale.

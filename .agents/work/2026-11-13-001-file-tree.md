# File tree in the right sidebar

## Plan

`.agents/plans/2026-11-13-001-file-tree.md`

## Summary

`oxd` serves `directory.watch` from one shared `notify` watcher, the app core forwards each watch over a Tauri channel, and the right sidebar shows the viewed session's `cwd` as a tree that persists open folders and scroll per session. The plan's goal is met. At the user's request during the work, the right panel now starts open.

## Departures from the plan

- The right panel starts open (`Workbench`'s initial `visible.right` is `true`), at the user's request. This reverses assumption 7. The e2e spec no longer clicks the toggle.
- The tree uses plain nested `ul`/`li` without `role="tree"`, `treeitem`, or `group`. Biome's a11y rules reject those widget roles on items that cannot take focus, and the plan leaves keyboard navigation out (assumption 4). Folder buttons still carry `aria-expanded`.
- A tree row's `sidebar-row tree-row` class sits on a `div` inside the `li`, because the `li` also holds the folder's nested list.
- Two CSS rules beyond the indent and the scrolling region. `.tree-spacer` holds the chevron's place in file rows, since an empty `.status` draws a dot. `.sidebar-body ul` resets lists for both sidebars and replaces the `.sessions` rule.

## Decisions

- `Directories` keeps a separate lock for the watcher and for the path map. The event handler locks only the map, and the map's lock is never held during a watcher call: notify's FSEvents watcher joins its callback thread when it changes paths, so holding the map lock there could deadlock.
- When the stream re-resolves after a failed read and lands on the same directory, it keeps its existing receiver. A fresh receiver would drop a change that was signalled between the read and the re-resolve.
- If the watcher refuses an ancestor (for example, it was removed after it was found), `Directories::watch` tries the next ancestor up.
- `useDirectory` sends `unwatch_directory` with the Tauri channel's `id`.

## Follow-up work

- No automated test covers scroll restore or persistence across a restart. The e2e spec covers live listing and keeping open folders across a session switch.
- `Changes` unwatches in `Drop`, which runs on the async runtime thread. On macOS that restarts the FSEvents stream there; it is not done in `spawn_blocking`.
- `Directories::watch` panics (`unreachable!`) if even `/` cannot be watched. That ends only the stream's task.
- The Linux inotify TODO in `directories.rs` is still open.

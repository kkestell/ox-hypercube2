# Event times and run timeline times

## Plan

`.agents/plans/2026-11-16-004-event-times.md`

## Summary

Every event carries and saves the time `oxd` recorded it, runs save `ended_at`, each conversation item reaches the webview as a `ConversationUpdate` with the time its key first appeared, and the run view shows `HH:MM` beside each agent message and beside a failed run's notice. The plan's goal is met.

## Departures from the plan

- `ui/src/features/composer/Composer.test.tsx` builds conversation updates too, so it gained `recorded_at: 0` like the other UI tests. The plan did not list it.
- `crates/oxd/tests/daemon.rs` needed no restored-run test; `runs_survive_a_restart_and_running_ones_are_interrupted` in `runs.rs` already restores an interrupted run and now asserts its `ended_at` is unset. `daemon.rs` changed only where a test inserts events with raw SQL, which now names `recorded_at`.
- No development databases exist: there is no `target/dev/oxd.sock.db` in `/Users/kyle/src/ox` or in any worktree. The script ran only on a copy of the installed database. The installed database still needs it when the new build is installed.

## Decisions

- `SavedRun` and `RunRecord` carry `ended_at`, so `Run::new` restores it and `Run::update` saves it with every change.
- `RunStatus.tsx` exports `RunNotice` (the notice's text, step index and time) and `clock`. `RunView.test.tsx` uses `clock` to state the expected times.
- `.run-status-messages` defines `--message-indent`, the distance from the step's left edge to a message's text. The list's left padding is that indent, and `.run-status-entry-time` sits at its negative. `.run-status-time` and `.run-status-entry-time` share one rule for width, colour, size and alignment.
- `ConversationUpdate` in `conversation.rs` gets a serialization assertion, because the UI depends on `#[serde(flatten)]` producing a flat object.
- The run-status mock scenario adds a failed run with messages, and every ended mock run gets an `ended_at`.

## Manual verification

1. The migration script converts a real database once and leaves a migrated one unchanged.

   ```sh
   mkdir -p /tmp/ox-event-times-test
   python3 -I -c "import sqlite3; s=sqlite3.connect('file:$HOME/.local/share/ox/oxd.sock.db?mode=ro', uri=True); d=sqlite3.connect('/tmp/ox-event-times-test/oxd.sock.db'); s.backup(d)"
   python3 -I /tmp/ox-migrate-event-times.py /tmp/ox-event-times-test/oxd.sock.db
   python3 -I /tmp/ox-migrate-event-times.py /tmp/ox-event-times-test/oxd.sock.db
   sqlite3 /tmp/ox-event-times-test/oxd.sock.db "select count(*) from events; pragma integrity_check; pragma foreign_key_check;"
   ```

   The first run printed `added events.recorded_at, runs.ended_at` and the second `already migrated`. All 4386 events were kept, each with its session's `created_at`. The integrity check printed `ok`, and the foreign key check found nothing.

2. The new `oxd` opens the migrated copy and serves its history.

   ```sh
   ./target/debug/oxd --socket /tmp/ox-event-times-test/oxd.sock &
   ./target/debug/oxctl --socket /tmp/ox-event-times-test/oxd.sock ls
   ./target/debug/oxctl --socket /tmp/ox-event-times-test/oxd.sock run ls
   ./target/debug/oxctl --socket /tmp/ox-event-times-test/oxd.sock attach <session-id>
   ```

   It listed all 8 sessions and both runs. Attaching to an archived session replayed its 1218 events, each with `recorded_at` set. The copy was deleted afterwards.

3. The gutter layout was not looked at in the running app. To check it, run `cd ui && npm run mock` and open the `run-status` scenario.

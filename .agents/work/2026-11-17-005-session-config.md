# Ox records each session's config

## Plan

`.agents/plans/2026-11-17-005-session-config.md`

## Summary

`SessionInfo.config` is the session's config, saved in the new `sessions.config`
column (schema step 2, backfilled from each session's latest option report).
`session.new` records it, `session.set_config` replaces it, the daemon sends
every setting at start and resume without comparing, and a session without
one adopts the agent's reported model, effort and mode when it starts. The
composer shows only the record and disables its pickers while the session
starts. Pi's bridge refuses an effort Pi clamps. The plan's goal is met.

## Departures from the plan

- `scripts/smoke-acp.py` called `session.set_config_option`, so its
  `set_option` now reads the session's config, replaces the one setting, and
  sends `session.set_config`. Changing the model drops the effort: the first
  Pi run failed with `The agent refused effort medium: Pi runs
  openrouter/deepseek/deepseek-v4.1-flash-1017 at effort high, not medium`,
  the plan's intended refusal of a clamped effort carried over from Pi's
  default model.
- The adoption test ("a session restored with an empty config adopts the
  agent's values") is in `tests/import.rs`: an imported session is the
  reachable way to restore a session with an empty config.
- `a_session_resumed_while_its_agent_is_working_runs_until_the_agent_is_idle`
  now ignores `config_option_update`s, since a resume sends every setting.
- `crates/ox/src/conversation.rs:835` needed no change: it builds an
  `AgentStarted`, which keeps `config_options`.
- The store test that opened a pre-versioning database at version 1 now
  expects the latest version.

## Decisions

- A new session's refused settings leave its record as requested; only the
  first prompt is rejected.
- After a partial refusal, an accepted setting whose ID the config lacks is
  appended.
- `SessionComposer` builds a change on the config it last sent until the
  session's listed config changes, and drops it on an error. Without this, an
  effort change made before the model change's answer would send the old
  model again.
- `settingsOf` turns options into settings for both the draft and the session
  composer.
- Pi's bridge sends the `config_option_update` before refusing a clamped
  effort, with invalid params, since Pi has already changed level.
- The backfill selects each session's latest report with SQLite's `->>`.

## Manual verification

1. A copy of the real database (115 sessions, version 1) migrates to version
   2, and the 9 sessions whose history has an `agent_started` get configs.

   ```sh
   d=$(mktemp -d); sqlite3 ~/.local/share/ox/oxd.sock.db ".backup '$d/oxd.sock.db'"
   target/debug/oxd --socket $d/oxd.sock --idle-exit-ms 600000 &
   target/debug/oxd --stop --socket $d/oxd.sock
   sqlite3 $d/oxd.sock.db "PRAGMA user_version; select count(*), sum(config != '[]') from sessions"
   ```

   Observed `2` and `115|9`, with configs such as
   `[{"config_id":"model","value":"claude-opus-5-5"},{"config_id":"effort","value":"medium"},{"config_id":"mode","value":"auto"}]`.

2. `schema-2.sql` was generated by opening `schema-1.sql` with this build's
   `Store` through a throwaway test and dumping it with `sqlite3 .dump`,
   adding `PRAGMA user_version=2;` and removing the duplicate
   `sqlite_sequence` row that loading the dump creates.

# Pi sessions get the ox MCP server

## Plan

`.agents/plans/2026-11-15-006-pi-ox-mcp.md`

## Summary

`pi-acp` declares stdio MCP support, keeps the client's stdio servers on the session, and starts every Pi with `-e <temp dir>/pi-acp/mcp-servers.js` and `PI_ACP_MCP_SERVERS` when there are servers. `McpServer`, `McpServer::config` and `parse_mcp` now live in `acp-bridge` and serve both bridges. In the live Pi smoke run the agent titled its session through `ox`'s `set_title`, so the plan's goal is met.

## Departures from the plan

- `check_title_tool` was defined on `ClaudeRun`, not `SmokeRun`. It moved to `SmokeRun` so `PiRun.checks` can use it.
- The repo has no `.env`, so `make smoke-pi` ran without exporting `OPENROUTER_API_KEY`. Pi used the OpenRouter credentials in `~/.pi/agent/auth.json`.

## Decisions

- `check_pi_names` checks ASCII letters and digits, the same as Pi's `SERVER_NAME = /^[A-Za-z0-9_-]+$/` in `@earendil-works/pi-mcp`. An exact duplicate name is refused as a duplicate too.
- The fake Pi in the protocol tests appends `$PI_ACP_MCP_SERVERS` to `servers` only when the variable is set.

## Checks run

- `make check-rust`: passed. One earlier run exited 2 with its output discarded. Three reruns passed.
- `make check-scripts`: passed.
- `make smoke-claude`: passed, including `agent_set_title_through_ox_mcp`. This ran before `check_title_tool` moved to `SmokeRun`.
- `make smoke-pi`: the first run failed in `check_commands` because the model answered `OX_NATIVE_COMMAND_ copper-lantern`, with a stray space. The rerun passed, including `agent_set_title_through_ox_mcp`.

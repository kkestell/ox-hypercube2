# pi-acp core

## Plan

`.agents/plans/2026-11-14-002-pi-acp-core.md`

## Summary

`crates/pi-acp` is an ACP v2 bridge that runs one `pi --mode rpc --approve
--session-id <id>` per session. It answers each prompt with its `messageId` once
Pi accepts it, drives turns with `user_message` and `state_update`, reports
`background: []`, streams text and thinking, and reports tool calls with kinds,
locations, and diffs for `edit` and `write`. The Makefile builds and bundles it,
and the README lists it. The plan's goal is met.

## Departures from the plan

- `Updates::is_working` is left out. Nothing reads it: `Updates::idle` already
  sends nothing when no turn is running, so ending the turn when Pi exits needs
  no check first.
- `Bridge::initialize` is an associated function, because it reads no bridge
  state. Clippy flags an unused `&self`.
- The README install paragraph now says the app bundles the Claude and Pi
  bridges, since `make install` now copies `pi-acp` into the app.

## Decisions

- Tool titles use the first line of the argument, cut to 160 characters, as
  `claude-code-acp` does, so a multi-line `bash` command gets a one-line title.
- A tool `path` is resolved by joining it to the session's `cwd` and
  normalizing `.` and `..` lexically. Pi's `~` expansion and `@` stripping are
  not reproduced.
- The new-file patch for `write` includes `new file mode 100644` and a
  `\ No newline at end of file` marker where needed, as Git writes them.
- Images in a prompt keep their MIME type. Pi decides which types it accepts.
- When Pi exits, prompts still waiting for its answer fail with the exit error,
  including when the session is closing. This follows the plan as written.
- `git_patch` keeps the jsdiff patch from its first `@@` line. A local `TODO`
  covers Git quoting of unusual path characters.

## Manual verification

1. With the installed Pi 1.4.0, `session/new` starts Pi, Pi stays up until
   `session/close`, and the close is answered once Pi exits.

   ```sh
   D=$(mktemp -d) && mkdir $D/bin $D/proj
   printf '#!/bin/sh\necho start $(date +%%s) >> %s/log\n/opt/homebrew/bin/pi "$@" 2>/dev/null\necho exit $? $(date +%%s) >> %s/log\n' $D $D > $D/bin/pi
   chmod +x $D/bin/pi
   # Run target/debug/pi-acp with PATH="$D/bin:$PATH"; send initialize,
   # session/new with cwd $D/proj, wait 4 s, then session/close.
   cat $D/log
   ```

   Observed: Pi started at `session/new`, ran for 4 s, and exited with status 0
   in the same second the close response arrived. Pi wrote only its
   "creating a new session with that id" warning to stderr. `ps` does not find
   Pi by its arguments, because Pi changes its process title.

   No prompt was sent to the real Pi, so Pi 1.4.0's prompt, event, and tool
   records are checked only by the fake `pi` in the tests. Task 6's smoke
   check covers a live model run.

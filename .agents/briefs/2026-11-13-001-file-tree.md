# File tree in the right sidebar

## Problem

The right sidebar is empty. Users have no way to see the files of the
directory a session works in without leaving the app.

## Outcome

- The right sidebar shows a file tree of the viewed session's directory: the
  workspace's directory, or the session's worktree. Folders expand and
  collapse like VS Code's explorer. Files cannot be opened yet.
- A new session shows its tree as soon as its directory exists, before the
  first message is sent.
- The tree updates when files are added, removed, or renamed, whoever makes
  the change.
- Version-control folders (`.git`, `.hg`, `.svn`, `.jj`, `CVS`) and OS
  clutter files (`.DS_Store`, `Thumbs.db`) never appear.
- Switching to another session and back restores that session's open folders
  and scroll position, including after the app restarts.
- Large workspaces stay fast: only the folders the user opens are read, and
  the work does not grow with the size of the workspace.

## Decisions

- **oxd lists directories and watches for changes.** The architecture puts
  everything every client must see kept up to date in oxd, other clients
  such as `oxctl` get the same listing, and it sits beside future file
  writes, which belong in oxd. Turned down: the app's Rust core reading the
  filesystem itself, which needs no protocol change but puts filesystem
  knowledge in two processes.
- **A fixed hidden list, gitignored entries shown.** VS Code, Zed, and
  JetBrains all hide the same version-control folders and OS clutter and
  show gitignored entries such as `node_modules` and `target`, which cost
  nothing while collapsed. Turned down: marking ignored entries now so the
  UI can dim them, and hiding ignored entries, which hides files people do
  look at, such as `.env`.
- **Tree state lasts across restarts.** Each session's open folders and
  scroll position are kept in the UI's local storage, as VS Code keeps them
  per workspace, and a deleted session's stored state is removed with it.
  Turned down: keeping it only until the app quits.

## Out of scope

- Opening, previewing, or editing files.
- Dimming or otherwise marking gitignored entries.
- A setting to change the hidden list.

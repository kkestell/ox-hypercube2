# Agent messaging, transcripts, and session creation

## Problem

Agents in Ox need a way to coordinate with other sessions, read what happened in a session, and ask the user to start a separate conversation for new work.

## Outcome

- Agents in standalone sessions can find and message other standalone sessions across workspaces without approval. A message starts a turn for an idle recipient or steers a busy recipient at its next opportunity.
- A message wakes a parked recipient or loads a resumable recipient after a daemon restart. Ox refuses messages to archived or deleted sessions and sessions that failed to start.
- Agents can read the retained transcript of any session without approval, including parked and archived sessions.
- An agent can ask to start a session with a required first prompt and specify the workspace, checkout or worktree, branch, harness, model, and effort. Ox starts the session with that prompt as soon as the user approves. Declining creates no session or worktree.
- The new session is independent. It has its own conversation and sends no automatic progress or results back to the requesting session.

## Decisions

- **Steer a busy recipient.** A peer message may carry a reply the recipient can use during its current turn.
- **Wake a parked recipient.** A session can park while it is waiting for a reply.
- **Stop ends the current turn.** A later peer message can start a new turn. If the user's queued prompts are held after Stop or a failed turn, they still wait for the user to send again.
- **Use Hypercube’s compact transcript.** Show user and agent messages, tool names, and how each turn ended.
- **A named worktree branch must already exist locally.** Reject a missing branch so a typo cannot start work from the wrong commit. If the branch is omitted, Ox creates its usual autogenerated branch from the workspace checkout’s `HEAD`.
- **The current checkout keeps its branch.** If the agent specifies a branch for the current checkout, it must match the branch already checked out.
